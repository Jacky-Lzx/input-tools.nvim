*input-tools.txt*  Command-line and prompt UI for Neovim 0.10+

SETUP                                                        *input-tools*
>
    require("input-tools").setup({})
<
No runtime dependencies. The plugin draws the native command line near the
bottom and leaves editing, history, search and completion with Neovim. require()
alone does not attach UI. It does not replace vim.ui.input/select/notify or keys.

CONFIGURATION                                         *input-tools-config*
>
    require("input-tools").setup({
      notifications = true,
      return_prompt = "auto", -- "show" waits for Enter.
      status = true,
      window = {
        border = "rounded", max_width = 80, max_height = 8,
        bottom = 1, winblend = 0, zindex = 250,
      },
      popupmenu = { enabled = true, max_height = 8, max_width = 60 },
    })
<
Long commands scroll horizontally. Prompt/context height is bounded.
window.row optionally sets a zero-based top offset (e.g. 3 for a top-centered
command palette), overriding bottom placement. Small screens clamp the position.
Completion menus use the available space below/above the input without overlap.
Nested command lines, expression input and multiline definition blocks are supported.
With popupmenu.enabled=true both native command-line and insert completion menus
are drawn here. Neovim still owns selection/acceptance keys and completion
sources. For command-line popup completion, use wildoptions=pum and wildmode=full.
The plugin does not change these options or provide syntax parsing.
Native popupmenu options: border="single", min_width=1, max_width=60,
max_height=8, align="frame" (or "cursor" for command-argument anchoring),
scrollbar=true. Insert menus remain cursor-relative. Long candidates are clipped
by display cells, with a reserved scrollbar column when items overflow. Menus
choose available space and shrink without overlapping the input. Blink uses its
own appearance settings; its adapter shifts wide menus left near the screen edge.

Input-specific layouts: profiles.command/search/input/expression/confirm are
window overrides for :, / and ?, input(), = and interactive prompts respectively.
window.width is a positive cell count or fraction in (0,1] of editor columns;
min_width/max_width bound it, with screen space taking precedence. Without width,
max_width retains its previous behavior. window.col offsets horizontal center.
window.title is a centered border string, or false (default); no border omits it.
Example: profiles = { search = { width = 0.4, title = "Search" } }.

BLINK.CMP                                             *input-tools-blink*

Blink's default completion.menu.cmdline_position reads vim.g.ui_cmdline_pos.
Input-tools publishes this shared screen position while native input is visible,
including layout/scroll offsets, and releases it when input closes. No Blink
dependency or early loading is required. Custom Blink positioning callbacks
should honor this value. Teardown restores a previous value only if still owned.
Layout changes coalesce a refresh of an already-loaded Blink menu on the next
event-loop turn. This guarded call uses Blink's internal menu positioning method;
no Blink modules are loaded or patched, and completion behavior stays with Blink.

For matching outer borders, merge the following into Blink's opts:
>
    local menu = opts.completion.menu or {}
    opts.completion.menu = vim.tbl_deep_extend("force", menu,
      require("input-tools.blink").menu_config(menu))
<
This configures public position/direction callbacks and compensates candidate
alignment using an already-loaded renderer's guarded internal offset accessor.
Both left borders align and the menu stays outside the input border. No columns,
icons, padding or keys are changed. Insert-mode direction and supplied position
callbacks are preserved when this input renderer is inactive. Evaluate these
options after input-tools is on runtimepath.

The default return_prompt=auto acknowledges only hit-enter prompts. Confirm,
numbered choice and substitution prompts always wait for the user's answer.
return_prompt=show displays the hit-enter prompt until answered. Externalized
showmode/showcmd/ruler widgets are displayed unless status=false.
Old unnamed numbered-choice messages in r/rm prompt states are also interactive;
they stay visible while inputlist() waits for the user's number.

Highlight groups: InputToolsNormal, InputToolsBorder, InputToolsPrompt,
InputToolsMenu, InputToolsSelection, InputToolsStatus. Colors link to native
theme groups and may be overridden using nvim_set_hl/ColorScheme autocmds.
Native input/context/prompt chunk colors are preserved, including input()
highlight callbacks. On old protocols, a guarded LuaJIT integer-only bridge
resolves matching groups; unavailable/unmatched attributes use the base color.
No C structures are read. Modern protocols use supplied group IDs directly.

NOTIFICATIONS                                  *input-tools-notifications*
>
    require("notification-tools").setup({ messages = { enabled = true } })
    require("input-tools").setup()
<
Input-tools owns command-line/prompt/completion UI, notification-tools owns
non-interactive messages and notifications. No hard dependency: input-tools
joins only an already loaded notification-tools instance. Without a handoff,
native messages retain their current owner. notifications=false disables joining.

The renderer attaches before calling notification-tools.attach_messages(). Its
returned handle is released before this renderer stops. Both loading orders and
notification reconfiguration work with NotificationToolsReady User events. Older
versions lacking that event need notifications loaded first or a manual call to
sync_notifications() after notification setup. Repeated input setup replaces its
old instance and acquires a fresh handle.

Disable competing Noice command-line/message/popup-menu owners. Connected GUIs
already externalizing these widgets are detected before attachment. Lua owners
cannot be enumerated automatically. No notification UI is bundled here.

API                                                      *input-tools-api*

setup(opts?)             Validate, replace the old instance, attach and join.
teardown()               Release message handle, UI callback, floats/autocmds.
is_enabled()             True while our UI subscription is active.
status()                 { enabled=boolean, notifications=boolean }.
get_window()             Visible input window ID, or nil; does not load UI.
sync_notifications()     Retry the handoff after an already loaded producer setup.

Invalid configuration preserves the working instance. UI errors disable this
renderer and release messages to restore native input. Stale scheduled callbacks
cannot affect a newer instance. No idle refresh timer is retained.

See :checkhealth input-tools. vim.ui_attach and nvim__redraw are experimental.
